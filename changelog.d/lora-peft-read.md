### Added

- New crate `mlmf-lora` (depends on `mlmf-core` alone, no I/O). `AdapterConfig::from_source` reads the declared `adapter_config.json` fields from any `MetadataSource`, every field `Option`: an absent `r` is `None`, never PEFT's class default of 8, and no scale is computed. `use_rslora` / `fan_in_fan_out` keep how they were declared (`Flag::Bool` or `Flag::Text`, measured as both), `target_modules` is a list or a single string, `rank_pattern` / `alpha_pattern` entries are read per module, and a key that is declared but unreadable (`null`, `{}`, wrong type) is listed in `unreadable`, never reported absent. `pair_tensors` pairs `lora_A` / `lora_B` (and `lora_embedding_A` / `_B`) by name; every input tensor lands in `pairs`, `orphans` or `others`, so `lm_head.base_layer.weight` is kept, not dropped.
- Verified: unit tests over a fake source, and `mlmf-conformance/tests/lora_adapter.rs` over `ConfigJson` and the tensor rows of seven real adapters in `lora-measurements.tsv` (population, pair, orphan and other counts asserted per file). Three sabotages (default `r` to 8, drop non-LoRA tensors, skip key unescaping) each turned a test red. The unescaping one is a real finding: `ConfigJson` escapes dots in nested keys, so a module-name pattern key arrived as `layers\.0\.v`. A non-empty `rank_pattern` and a string `target_modules` were not found on the Hub; those cases are synthetic.
- GGUF reading, writers and the round trip are later steps. `Cargo.lock` carries the new crate's entry, which a new member requires; no version line is edited.
