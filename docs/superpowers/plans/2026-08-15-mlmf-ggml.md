# mlmf-ggml Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A dependency-light crate that knows the geometry of every live ggml quantization type — 35 codes — and projects each one onto `mlmf_core::Encoding`, so no consumer ever re-derives block arithmetic and gets it subtly wrong.

**Architecture:** One `#[non_exhaustive]` enum over ggml's closed code space, one table, and three questions it can answer: what is this code, how big is a tensor of this type, and can these bytes be borrowed as typed blocks. It performs no I/O, parses no container, and interprets nothing. `mlmf-gguf` will consume it; a future `mlmf-ggjt` reuses it unchanged, which is why it is a crate and not a module inside the GGUF reader.

**Tech Stack:** Rust 2024, `mlmf-core` only. No `unsafe`. No new third-party dependencies.

**Spec:** `docs/superpowers/specs/2026-08-14-backend-agnostic-mlmf-design.md` (§4.1 Encoding, §4.6 alignment, §7 unknowns, §9 MFIS clauses, §11 crate disposition, §12 sequencing)

## Why this crate exists, in one measurement

Fuel's `GgmlDType::from_u32` (`fuel-ir/src/quantized.rs:35`, rev `8771997e`) accepts 15 codes and errors on everything else. The live ggml code space is **35**. A 29-file corpus of ordinary HuggingFace downloads contains 540 `IQ4_NL` tensors, 30 `IQ3_S` and 30 `IQ4_XS` — three codes in the missing 20. Those files are not exotic; they are what the Hub serves. The gap is not a feature request, it is the difference between reading the Hub and refusing it.

## Global Constraints

Copied verbatim from the spec; every task's requirements implicitly include these.

- **C1 — one dependency edge per capability.** `mlmf-ggml` depends on `mlmf-core` and nothing else. Not `half`, not `num-traits`, not `bytemuck`.
- **C3 — purity.** No filesystem, no network, no process spawning, no clock. Enforced by a gate, not by intention. `std` use is restricted to an allow-list of submodules.
- **`#![forbid(unsafe_code)]`, `#![warn(missing_docs)]`** at the crate root, matching `mlmf-core`.
- **Extend by data, not by variant (§4.1).** A new quantization scheme is a new row, never a new `Encoding` variant.
- **Absent means not declared (§5).** Never a default.
- **Loud unknowns (§7).** An unrecognized code is representable and reportable, never silently coerced and never a bare `Result` that destroys the caller's ability to describe it.
- **AD-2 — proven able to fail.** No test is trusted until it has been made to go red by sabotaging the code it covers.
- **Clippy is a gate:** `cargo clippy --all-targets -- -D warnings` must pass.

## The contract that shapes the API

`mlmf-gguf` must be able to open a file, read all its metadata, and report an unrecognized tensor type **without the open failing**. This is possible because GGUF stores each tensor's offset explicitly rather than deriving it by accumulating sizes — so an unknown code costs exactly one tensor's *length* and nothing else.

That forces one API decision, and it is the most important one in this plan:

> **`mlmf-ggml` never returns `Err` for an unrecognized code.** Refusing to construct a value would leave the container holding a raw `u32` and nothing else, and the container would then be tempted to rebuild the geometry locally — putting the type table in two places, which is the exact duplication this crate exists to prevent.

`from_code` returns `Option`. `code_status` returns a three-state enum. Neither can fail.

## The three-bucket vocabulary

An unrecognized code has **three** causes, not two, and they send an operator in different directions:

| Status | Meaning | What an operator should do |
|---|---|---|
| `Known(GgmlType)` | in this build's table | nothing |
| `Retired { name }` | ggml **removed** this code; old files still carry it | look *backward* — the file is old, not corrupt |
| `Unassigned` | never assigned, or newer than this build | look *forward* — upgrade, or the file is damaged |

Collapsing `Retired` into "unknown" produces a true-sounding message about the wrong cause: telling someone holding a 2023 file to upgrade their software. ggml has **eight** retired codes, so this is not a hypothetical bucket.

## Task 1: `ErrorKind::RaggedRow` in mlmf-core

ggml's divisibility rule is not the one `mlmf-core` currently enforces, and the difference is a real hole rather than a pedantic one.

`Encoding::byte_size` checks that the **total element count** is a whole number of blocks. ggml checks that the **first dimension** is (`gguf.cpp:723`, `info.t.ne[0] % blck_size != 0`). For a Q4_0 tensor of shape `[16, 64]`: `ne[0] = 16` is not a multiple of 32, so ggml rejects the file — but the total is 1024, which *is* a multiple of 32, so `mlmf-core` accepts it and computes a byte size that no ggml writer ever produced. Handing out that number is precisely the "exactly correct answer that does not run" the spec exists to prevent.

Core cannot enforce the row rule itself — it is a property of block-quantized *layouts*, and core does not know a given `Encoding` came from a row-major quantized format. So core gains the vocabulary and `mlmf-ggml` applies it.

**Files:**
- Modify: `crates/mlmf-core/src/error.rs` (add variant after `RaggedBlock`, ~line 63)
- Test: `crates/mlmf-core/src/error.rs` (inline `mod tests`)

**Interfaces:**
- Produces: `ErrorKind::RaggedRow { name: String, row_len: u64, elements_per_block: u64 }`

**Three facts in this table that will bite an implementer who skims it:**

1. **Four alignments are not 2.** `Q8_K` is 4 (it leads with a `float`), and `IQ1_M`, `MXFP4`, `NVFP4` are 1 (no member wider than a byte). An implementation that hardcodes 2 for "quantized" is right 23 times out of 27 and wrong in a way no ordinary file reveals.
2. **`MXFP4` is 17 bytes — odd.** Block boundaries inside such a tensor land on odd offsets. This is fine because its alignment is 1, but any code that assumes block sizes are even is wrong.
3. **Geometry does not identify a type — and this is the crate's central hazard, not a curiosity.** Counting only the quantized rows, three pairs share both numbers exactly: `Q4_0`/`IQ4_NL` (32/18), `Q3_K`/`IQ3_S` (256/110), `IQ2_XXS`/`TQ2_0` (256/66). The code must be carried, never inferred from the size; a lookup keyed on geometry silently decodes one as the other, and on the dense side that means handing a consumer integer bytes to reinterpret as floats.

   This count was wrong in an earlier draft of this plan, which said "three" — the quantized-only figure — and a Task 7 test built on that number was named as though it enumerated the hazard when it covered one eighth of it. `every_pair_sharing_a_geometry_is_enumerated_and_agrees_on_size` in `geometry.rs` now derives the set rather than listing it, so the next collision is caught on the day it lands rather than the day someone recounts.

```rust
//! ggml's type codes and their geometry.

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn a_known_code_resolves_to_its_geometry() {
        let t = GgmlType::from_code(2).expect("Q4_0 is code 2");
        assert_eq!(t.name(), "Q4_0");
        assert_eq!(t.elements_per_block(), 32);
        assert_eq!(t.bytes_per_block(), 18);
        assert_eq!(t.alignment(), 2);
        assert!(t.is_quantized());
    }

    #[test]
    fn geometry_does_not_identify_a_type() {
        // Q4_0 (2) and IQ4_NL (20) have identical block geometry: 32
        // elements, 18 bytes. They are different quantizations with
        // different codebooks. Any lookup keyed on size decodes one as the
        // other and produces plausible garbage, so the code must survive
        // the round trip.
        let a = GgmlType::from_code(2).unwrap();
        let b = GgmlType::from_code(20).unwrap();
        assert_eq!(a.elements_per_block(), b.elements_per_block());
        assert_eq!(a.bytes_per_block(), b.bytes_per_block());
        assert_ne!(a, b);
        // Deliberately NOT `assert_eq!(a.code(), 2)`: `from_code` returns
        // the item satisfying `t.code() == code`, so that assertion is
        // true by construction and cannot fail independently of the
        // `unwrap` above. Pin the names instead, which the table supplies
        // separately from the code.
        assert_eq!(a.name(), "Q4_0");
        assert_eq!(b.name(), "IQ4_NL");
    }

    #[test]
    fn the_four_types_that_are_not_two_byte_aligned() {
        // Exact values, not `is_power_of_two()`: that assertion is
        // satisfied by a body that returns 2 unconditionally, which is what
        // a skimmed reading of the table produces.
        assert_eq!(GgmlType::from_code(15).unwrap().alignment(), 4); // Q8_K
        assert_eq!(GgmlType::from_code(29).unwrap().alignment(), 1); // IQ1_M
        assert_eq!(GgmlType::from_code(39).unwrap().alignment(), 1); // MXFP4
        assert_eq!(GgmlType::from_code(40).unwrap().alignment(), 1); // NVFP4
        assert_eq!(GgmlType::from_code(2).unwrap().alignment(), 2); // and the common case
    }

    #[test]
    fn a_dense_type_is_one_element_per_block_and_not_quantized() {
        let f32t = GgmlType::from_code(0).unwrap();
        assert_eq!(f32t.elements_per_block(), 1);
        assert_eq!(f32t.bytes_per_block(), 4);
        assert!(!f32t.is_quantized());
    }

    #[test]
    fn an_unknown_code_is_none_never_an_error() {
        // The container must be able to report an unrecognized tensor
        // without its open failing. A Result here would leave it holding a
        // bare u32 and tempt it to rebuild the geometry locally.
        assert!(GgmlType::from_code(4).is_none());
        assert!(GgmlType::from_code(31).is_none());
        assert!(GgmlType::from_code(9999).is_none());
    }

    #[test]
    fn a_retired_code_is_distinguishable_from_one_that_never_existed() {
        // Retired means the file is OLD. Unassigned means the file is new
        // or damaged. Collapsing them tells an operator holding a 2023
        // file to upgrade their software, which is a true-sounding message
        // about the wrong cause.
        match GgmlType::status(4) {
            CodeStatus::Retired { code, name } => {
                assert_eq!(code, 4);
                assert_eq!(name, "Q4_2");
            }
            other => panic!("code 4 is retired, got {other:?}"),
        }
        match GgmlType::status(38) {
            CodeStatus::Retired { name, .. } => assert_eq!(name, "IQ4_NL_8_8"),
            other => panic!("code 38 is retired, got {other:?}"),
        }
        assert!(matches!(
            GgmlType::status(9999),
            CodeStatus::Unassigned { code: 9999 }
        ));
        assert!(matches!(GgmlType::status(2), CodeStatus::Known(_)));
    }

    #[test]
    fn the_live_and_retired_lists_cannot_drift_into_disagreement() {

        // place that is checked — so it must be checked in BOTH directions,
        // and against the real lists rather than a copy of one.
```

```rust
///
/// Three states, not two. "Unknown" collapses a file that is **old**
/// together with one that is **new or damaged**, and those send an
/// operator in opposite directions.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
#[non_exhaustive]
pub enum CodeStatus {
    /// In this build's table.
    Known(GgmlType),
    /// ggml removed this code. Files predating the removal still carry it.
    Retired {
        /// The code as declared.
        code: u32,
        /// The name ggml used before removal.
        name: &'static str,
    },
    /// Never assigned by ggml, or newer than this build.
    Unassigned {
        /// The code as declared.
        code: u32,
    },
}
```

```rust
//! whole-tensor one.

#[cfg(test)]
mod tests {
    use crate::GgmlType;
    use mlmf_core::{DType, Encoding, ErrorKind};

    #[test]
    fn every_dense_type_projects_to_its_own_scalar_type() {
        // All eight, not a spot check — and the reason is the same lesson
        // the quantized side already encodes. The dense types fall into
        // equal-width groups: {F16, BF16, I16} are all 2 bytes, {F32, I32}
        // both 4, {F64, I64} both 8. A mapping that returns the wrong
        // member of a group changes no size anywhere, so
        // `every_live_type_computes_a_size_for_a_shape_it_permits` stays
        // green, and a consumer reinterprets i32 bytes as f32 with no error
        // raised at any layer. Width does not identify a scalar type any
        // more than block geometry identifies a quantization.
        let expected = [
            (GgmlType::F32, DType::F32),
            (GgmlType::F16, DType::F16),
            (GgmlType::BF16, DType::BF16),
            (GgmlType::F64, DType::F64),
            (GgmlType::I8, DType::I8),
            (GgmlType::I16, DType::I16),
            (GgmlType::I32, DType::I32),
            (GgmlType::I64, DType::I64),
        ];
        for (t, dt) in expected {
            assert_eq!(t.encoding(), Encoding::Dense(dt), "{}", t.name());
        }
        // And nothing else is dense. Without this, a quantized type that
        // fell through to the dense arm would be caught by nothing above.
        let dense: Vec<&str> = GgmlType::ALL
            .into_iter()
            .filter(|t| matches!(t.encoding(), Encoding::Dense(_)))
            .map(GgmlType::name)
            .collect();
        assert_eq!(dense.len(), 8, "dense set drifted: {dense:?}");

        // else to go on.

            panic!("Q4_0 is quantized");
```

```rust
use mlmf_core::{BlockSpec, DType, Encoding, Error, ErrorKind, Result};

use crate::GgmlType;

impl GgmlType {
    /// This type as `mlmf-core` describes encodings.
    ///
    /// Dense types become [`Encoding::Dense`]; everything else becomes a
    /// [`BlockSpec`] **carrying the ggml code**, which is the only thing
    /// separating types with identical geometry — `Q4_0` and `IQ4_NL` are
    /// both 32 elements in 18 bytes and are not interchangeable.
    #[must_use]
    pub fn encoding(self) -> Encoding {
        let dense = match self {
            GgmlType::F32 => Some(DType::F32),
            GgmlType::F16 => Some(DType::F16),
            GgmlType::BF16 => Some(DType::BF16),
            GgmlType::F64 => Some(DType::F64),
            GgmlType::I8 => Some(DType::I8),
            GgmlType::I16 => Some(DType::I16),
            GgmlType::I32 => Some(DType::I32),
            GgmlType::I64 => Some(DType::I64),
            _ => None,
        };
        match dense {
            Some(dt) => Encoding::Dense(dt),
            None => Encoding::Blocked(BlockSpec {
                family: "ggml",
                code: self.code(),
                elements_per_block: self.elements_per_block(),
                bytes_per_block: self.bytes_per_block(),
                alignment: self.alignment(),
            }),
        }
    }

    /// Bytes a tensor of shape `ne` occupies in this type.
    ///
    /// `ne` is in **declared order**, first dimension first — the same
    /// order GGUF writes it and the order `ggml_tensor::ne` uses. The
    /// first entry is the row length, and ggml requires it to be a whole
    /// number of blocks (`gguf.cpp`, tensor-info validation). That rule is
    /// stronger than whole-tensor divisibility and is checked here because
    /// `mlmf-core` cannot know an `Encoding` describes a row-major
    /// quantized layout.
    ///
    /// # Errors
    ///
    /// [`ErrorKind::RaggedRow`] if the first dimension is not a whole
    /// number of blocks; [`ErrorKind::ShapeOverflow`] or
    /// [`ErrorKind::SizeOverflow`] if the arithmetic does not fit a `u64`.
    pub fn nbytes(self, ne: &[u64], name: &str) -> Result<u64> {
        let per_block = self.elements_per_block();
        if let Some(&row) = ne.first()
            && per_block > 1
            && !row.is_multiple_of(per_block)
        {
            return Err(Error::from(ErrorKind::RaggedRow {
                name: name.to_string(),
                row_len: row,
                elements_per_block: per_block,
            }));
        }

        let mut elems: u64 = 1;
        for &d in ne {
            elems = elems.checked_mul(d).ok_or_else(|| {
                Error::from(ErrorKind::ShapeOverflow {
                    // Core declares `dims: Vec<usize>`; GGUF declares
                    // dimensions as `u64`. On every 64-bit target the
                    // conversion is exact. It is saturated rather than
                    // unwrapped because this is already the error path and
                    // a panic here would replace a describable failure with
                    // an undescribable one.
                    dims: ne
                        .iter()
                        .map(|&d| usize::try_from(d).unwrap_or(usize::MAX))
                        .collect(),
                })
            })?;
        }

        self.encoding().byte_size(elems, name)
    }
}
```

**Two API details already verified against the repo, so do not re-derive them:** `ErrorKind::ShapeOverflow` takes `dims: Vec<usize>` (not `Vec<u64>`), and `Encoding::byte_size` takes `(elem_count: u64, tensor_name: &str)` and returns `Result<u64>`. If either has changed since this plan was written, follow the code and adjust the test's expectations rather than adding a field to core.

**(i) `.gitattributes` — add a rule for `.tsv`.** The repo has `core.autocrlf=true` and no rule for this extension, so both committed fixtures materialise as CRLF on a fresh Windows checkout. That is currently **inert**: every consumer uses `include_str!` then `.lines()`, which strips the full `\r\n`, and a review verified this empirically by compiling the CRLF case. Add it anyway, beneath the existing `*.fixture` rule:

```
# The type-geometry fixtures are compared as text. `str::lines()` already
# tolerates CRLF, so this is defence against a future non-Rust consumer
# doing a byte comparison — which is exactly how the snapshot scar above
# happened.
*.tsv text eol=lf
```

**(ii) `tests/table.rs` — the comment on `the_fixture_itself_is_intact` gives a false reason.** It currently claims that if a merge mangled the TSV to three rows, "every other test in this file passes vacuously." That is untrue, and the task's own sabotage disproved it: `the_table_declares_nothing_the_ground_truth_does_not` iterates `GgmlType::ALL` and fails the moment any code is missing from a truncated fixture, so both tests went red together. Replace the justification with the real one:

```rust
    // The fixture's own shape, checked before anything trusts it.
    //
    // The genuine justification is the DUPLICATE-ROW case, which is the
    // one thing the other two tests cannot see: `every_ground_truth_row_is
    // _in_the_table` iterates both copies and both match, and
    // `the_table_declares_nothing_the_ground_truth_does_not` builds its
    // set with `Vec::contains`, which is duplicate-blind. Only the row
    // count notices.
    //
    // An earlier version of this comment claimed a truncated fixture would
    // make the other tests "pass vacuously". That was false — a truncated
    // fixture fails `the_table_declares_nothing…` immediately — and a
    // comment giving a wrong reason is how a load-bearing test gets deleted
    // later by someone who checks the rationale and finds it hollow.
```

**(iv) `crates/mlmf-core/src/error.rs` — the same over-broad claim, in a second place.** `ErrorKind`'s type-level doc says "The first four variants are the **fatal** unknowns of spec §7: they make byte-size arithmetic unknowable." `UnknownTypeCode` is the first of those four, so after Step 3 corrects `report.rs`, these two files contradict each other on the rule this plan established. Replace it with:

```rust
/// What went wrong, independent of which artifact it went wrong in.
///
/// Most variants here are the **fatal** unknowns of spec §7: they make
/// byte-size arithmetic unknowable, so continuing would hand out wrong
/// bytes rather than incomplete ones.
///
/// [`ErrorKind::UnknownTypeCode`] is the exception, and the exception is
/// the interesting part. Whether an unrecognised type code is fatal is a
/// property of the **container**, not of the code. It is fatal where
/// tensor offsets are derived by accumulating sizes, because one unknown
/// length poisons every address after it. It is merely loud where the
/// container stores each offset explicitly — as GGUF does — because the
/// cost is then confined to that one tensor, and metadata and every other
/// tensor stay readable. A format crate that can still address everything
/// else reports the code through [`crate::Report`] and keeps going.
```

**(v) `src/types.rs` — label the exhaustiveness gate, because nothing else marks it.** `GgmlType::row()` is the only thing preventing a new variant from being added without geometry: it is a 35-arm `match self` with no wildcard, so a new variant fails to compile. That protection is **structural and invisible**. `GgmlType` is `#[non_exhaustive]`, which means an identical-looking `match` written in an integration test — or in any crate other than this one — is *required* to carry a `_` arm and can therefore never break. Vulkane's architect hit exactly this: they wrote the enforcement in an integration test, it compiled clean, enforced nothing, and produced no warning of any kind. The broken version and the working version are the same code in different files.

So someone refactoring `row()` into a shared helper, or moving this check to `tests/table.rs` for tidiness, would produce a diff that looks like an improvement and silently disables the guard. Nothing in review would say so. Add the sign:

```rust
    /// The one place any type's geometry is stated.
    ///
    /// **This match is load-bearing as an exhaustiveness gate, and its
    /// location is part of the guarantee.** It has no wildcard arm, so
    /// adding a variant to `GgmlType` without giving it geometry fails to
    /// compile. That only works *inside this crate*: `GgmlType` is
    /// `#[non_exhaustive]`, so the identical match written in an
    /// integration test — or any other crate — is required to carry a `_`
    /// arm and can never break. Moving this into `tests/`, or collapsing
    /// it into a helper with a catch-all, removes the guard while leaving
    /// code that looks the same.
```

**(iii) `src/geometry.rs` — record why the dense-drift check is not redundant.** A review established that `every_live_type_computes_a_size_for_a_shape_it_permits` catches a wrongly-routed quantized type *today*, but only by arithmetic coincidence: no current quantized type has `bytes_per_block / elements_per_block` equal to 1, 2, 4 or 8 (`Q8_0` is nearest at 34/32). Append to the comment on the `dense.len() == 8` assertion:

```rust
        // Not redundant with the size-based coverage test, though it looks
        // it. That test catches a wrongly-routed quantized type only
        // because no current type's bytes-per-element ratio equals a valid
        // scalar width — Q8_0 is nearest at 34/32. That is a fact about
        // today's table, not a guarantee. This check is set membership, so
        // it holds regardless.
```

## Deliberately not in this crate

- **Dequantization.** Requires codebooks, target precision and device knowledge. Belongs to the consumer.
- **The GGUF container.** Header, metadata, tensor directory, alignment — all `mlmf-gguf`, the next plan.
- **GGUF v1 support.** Deferred to `mlmf-gguf`, where it is a container question rather than a type question. Note for that plan: current llama.cpp **refuses v1 outright** (`gguf.cpp:502`), so its reader is not a reference for the v1 layout, and a v1 file in the corpus (`tinyllamas-stories-260k-f32.gguf`) did not parse under a v2-shaped reader with only the width substitutions applied. The v1 layout must be derived from that file rather than assumed.
- **Legacy GGJT/GGML containers.** A future `mlmf-ggjt`, which will consume this crate unchanged. That reuse is the reason this is a crate rather than a module.
